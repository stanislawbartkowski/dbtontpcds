Welcome to your new dbt project!

This project uses [dbt-core](https://github.com/dbt-labs/dbt-core) with the
[dbt-duckdb](https://github.com/duckdb/dbt-duckdb) adapter to build models
against a local DuckDB database (`dev.duckdb`).

### Setup

Dependencies (`dbt-core`, `dbt-duckdb`) are installed into the `.venv`
virtual environment one level up from this project:

```bash
cd ..
.venv/bin/pip install -r requirements.txt
```

### Profile

The dbt connection profile lives in this project directory
(`profiles.yml`), not in the default `~/.dbt/profiles.yml`, so pass
`--profiles-dir .` (or `export DBT_PROFILES_DIR=$(pwd)`) when running dbt
commands from here:

```bash
../.venv/bin/dbt debug --profiles-dir .
```

### Using the starter project

Try running the following commands (from this directory):
- `../.venv/bin/dbt run --profiles-dir .`
- `../.venv/bin/dbt test --profiles-dir .`

### Project structure

- `models/staging/sources.yml` — declares the `raw_data` source, pointing
  at all TPC-DS tables loaded into the `raw` schema of `dev.duckdb`.
- `models/staging/*.sql` — one view model per raw table (`customer.sql`,
  `store_sales.sql`, etc.), each a straight
  `select * from {{ source('raw_data', '<table>') }}`. All staging models
  are materialized as `view`s (configured in `dbt_project.yml`).

## Raw data setup (TPC-DS)

This project sources TPC-DS data into a `raw` schema in the local DuckDB
database (`dev.duckdb`) before any dbt models run against it.

### 1) Create the tables in the raw schema

The table DDL comes from the TPC-DS tools (`tpcds.sql`). Create a `raw`
schema and run the DDL against it so the unqualified `CREATE TABLE`
statements land in `raw` instead of `main`:

```bash
cat > /tmp/load_raw.sql <<'EOF'
CREATE SCHEMA IF NOT EXISTS raw;
USE raw;
.read /home/dbt/tpc/DSGen-software-code-4.0.0/tools/tpcds.sql
EOF

duckdb dev.duckdb < /tmp/load_raw.sql
```

Replace /home/dbt/tpc/DSGen-software-code-4.0.0/tools/tpcds.sql with the location valid in your environment

Run this once to set up the 25 TPC-DS tables (`call_center`, `customer`,
`store_sales`, `web_sales`, etc.) empty in the `raw` schema.

### 2) Load the raw data

Use `scripts/load_raw_data.sh` to load the pipe-separated `.dat` files
generated by `dsdgen` into the `raw` tables:

```bash
./scripts/load_raw_data.sh <dat_directory> [duckdb_path]
```

- `<dat_directory>` (required) — directory containing the `.dat` files,
  e.g. `/home/dbt/tpc/DSGen-software-code-4.0.0/dat`
- `[duckdb_path]` (optional) — target `.duckdb` file, defaults to
  `dev.duckdb` in the project root

Example:

```bash
./scripts/load_raw_data.sh /home/dbt/tpc/DSGen-software-code-4.0.0/dat
```

The script `TRUNCATE`s each `raw` table before copying in the matching
`.dat` file, so it is safe to re-run to refresh the data.
